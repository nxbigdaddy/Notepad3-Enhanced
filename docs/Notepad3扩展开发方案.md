# Notepad3 扩展开发方案

日期：2026-10-11

## 已确认方向

基于 Notepad3 源码扩展，保持轻量 Windows 原生编辑器风格。范围包括 AI、多标签与分屏、文件树与会话、专用文本工具、界面优化、Markdown 实时预览。额外面板默认收起，AI 和预览按需初始化。

## 当前进度

已固定上游提交并完成本机构建。Markdown 预览、M 按钮、图表/公式与 HTML/PDF 导出，多标签、分屏、文件树、会话/异常恢复、AI 四操作与差异确认，以及日志/配置/批量文本工具均已接入。功能仍在验证和完善，尚未全部完成；实时证据与剩余要求见 [迭代进展](迭代进展.md) 和 [全部功能验收清单](全部功能验收清单.md)。以下调研与实施计划保留初始记录，不代表当前功能状态。

## 现有接入位置

- src/Notepad3.c：主窗口、消息分发、菜单命令和文件流程。WM_SIZE 路由到 MsgSize，可作为布局接入点；FileLoad/FileSave 是文件生命周期重点。
- 单文档耦合：g_hwndEditWindow、Globals.hwndEdit、Paths.CurrentFile、FileWatching，以及编码访问函数。引入标签前需审计所有文档状态和直接编辑器调用。
- src/Edit.*：编辑操作的重点审计入口。
- src/Styles.*、src/StyleLexers/：样式和语法高亮的重点审计入口。
- src/Dialogs.*、res/、language/：对话框、资源和本地化的候选接入位置。
- src/Config/、src/DarkMode/：配置和主题的候选接入位置。

以上候选位置仍需完整本地源码核实。

## 建议模块边界

1. DocumentManager：每份文档有独立 ID、版本、Scintilla 文档句柄、路径、编码、换行格式、修改状态和监控状态。
2. EditorView：负责编辑控件、当前文档绑定、光标、选区、滚动和折叠视图状态。一个文档可绑定多个视图。
3. WorkspaceLayout：管理标签栏、文件树、分隔条、编辑区域和可收起右侧面板。
4. MarkdownPreview：提取文本快照、延迟合并渲染请求、版本校验、相对资源解析和预览显示。
5. AiService：后台请求、取消、超时、凭据管理及结果差异。结果关联文档 ID、版本和目标范围，应用前检查原文是否变化。
6. TextTools：日志过滤、JSON 格式化、配置检查和批量文本处理，统一返回修改提案或只读结果。

不建议第一阶段构建通用第三方插件系统；先通过内部模块边界承载已确认功能。

## Markdown 候选方案

保留 Scintilla 编辑，右侧使用按需创建的 WebView2 显示离线 HTML。解析器优先评估 CommonMark/GFM 支持；WebView2 和解析器尚未选定，需核查官方接口、许可证及实际运行开销。

第一版：标题、列表、引用、表格、代码块、图片、任务列表、实时更新和正确的相对路径。后续再做滚动同步、Mermaid、数学公式和导出。

文档原始 HTML 默认禁用或净化；不允许文档内容直接调用宿主接口。远程资源加载策略需明确。预览需处理文档切换和过期渲染，运行时缺失时编辑器仍应正常工作。

## 实施顺序与验收

### 0. 基线

重新取得源码、固定提交、检查仓库指令和许可证、核实依赖与 C++ 工具链、构建 x64 Release。运行原版并记录启动时间、空闲内存、打开文件与保存行为。

### 1. 文档状态和多标签

先提取文档状态，再增加标签栏。验证各标签的内容、撤销、编码、路径与保存不会串用；关闭未保存文档逐一确认。会话恢复需包含未保存缓冲区及异常退出恢复设计。

### 2. 布局和 Markdown

加入可调整右侧面板与 Markdown 预览。验证中文、相对图片、连续输入、切换标签、关闭预览、不同 DPI，以及运行时缺失的退化行为。对比关闭预览时的启动和内存基线。

### 3. AI

先提供一个可配置服务接口和选区操作：解释、翻译、改写、生成；加入差异预览、取消和一次撤销。验证请求途中编辑、切换、关闭文档后，返回结果不会错误覆盖内容。模型服务、协议和凭据方式尚待选择。

### 4. 专用工具、分屏和界面

逐步加入日志筛选、JSON 格式化、文件树、分屏和视觉优化。批量操作先展示文件列表与变更结果。验证共享文档视图一致性、后台扫描不阻塞编辑、撤销和错误反馈。
