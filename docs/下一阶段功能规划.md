# 下一阶段功能规划

日期：2026-10-11。状态：规划，尚未实施。用户明确提出文件搜索、打开历史管理、多平台 AI、百度网盘授权同步；本文新增建议和实施先后为待确认方案，不能作为已交付功能。

## 现有基础

已有文件树、多标签、会话恢复，以及单服务配置的 AI 解释/翻译/改写/生成、异步请求取消、差异确认和撤销。下一阶段在这些基础上扩展。文件树不等于递归文件搜索，会话归档不等于打开历史；已有 AI 文本兼容协议不等于已完成国内供应商实测。

## 1. 文件搜索

- 选择一个或多个搜索根目录，支持递归子目录；默认当前工作目录，不默认扫描所有磁盘。
- 类型过滤默认 .md，支持 .markdown、.txt、.json、.ini 及自定义扩展名；支持预设和全部类型。
- 先列出所有匹配文件，按名称、路径、修改时间、大小筛选排序；双击在标签中打开，已打开文件定位原标签。
- 文件内容搜索作为第二步，支持关键词、大小写、整词与正则，列出匹配行及上下文，点击定位。
- 后台枚举，分批显示，可取消；目录读取错误反馈但不丢弃其他结果。排除目录可配置，默认跳过版本控制、构建依赖、补丁备份等目录；目录链接不默认递归。
- 与文件树共享根目录选择与文档打开入口。未保存编辑不因搜索或打开重复文件被覆盖。
- 先实现文件列表与过滤，再依据实测规模决定是否引入持久索引；语义索引不是首版必需。

验收：中文路径、多根目录、类型切换、文件新增/删除、无权限目录、大目录分页与取消、重复打开和未保存标签保护。

## 2. 打开文件历史管理

- 独立历史面板，记录路径、最近打开时间、打开次数，可搜索、筛选类型及排序。
- 收藏/置顶常用文件；打开记录可恢复已保存的阅读位置，工作区中已打开文件直接激活。
- 支持移除单条、清空历史、暂不记录历史；移除历史不删除原文件。
- 文件不存在时保留可识别的失效标记，可重新定位；路径去重兼顾 Windows 大小写规则。
- 历史条数上限可配置；不同进程协调持久化写入，避免最后退出的实例覆盖其他实例的历史。
- 普通文件历史默认仅保存路径与元数据，不额外存全文。内容版本管理另作为独立可选功能。

验收：跨进程持久化、中文和长路径、重复打开、失效路径、置顶、删除记录不删文件、关闭记录开关。

## 3. 多平台 AI

### 配置

服务配置列表支持 Kimi、DeepSeek、Qwen/阿里云百炼预设及自定义第三方兼容接口。每个配置包含名称、服务地址、API Key、模型标识、超时、输出长度与可用模型参数。支持多个账号、多个服务和快速切换；连接测试独立显示认证、模型、网络、额度和限流错误。可获取模型列表的平台允许自动读取，其他平台手动输入，不把动态模型名写死。

不同平台/地域/产品的地址与密钥需匹配。第三方平台优先接入 Chat Completions 兼容协议；非兼容协议通过明确适配器支持，不宣称任意网址均能使用。模型能力记录流式、思考模式、结构化输出等，缺少支持时不发送相应参数。

API Key 延续 Windows Credential Manager 保存，支持独立配置 ID，避免同服务不同账号混用。普通设置文件、日志、更新包和云同步不包含凭据。

### AI 功能顺序

第一批：保留解释、翻译、改写、生成；新增摘要、润色、扩写/缩写、纠错、自定义提示词模板，以及针对当前文件的问答。

第二批：Markdown 大纲/标题/表格/Mermaid 草稿生成、待办提取、代码/配置解释与错误分析、文档格式整理。支持连续对话、流式显示和停止；思考内容与最终可应用答案分开处理，截断结果不视为完整修改。

第三批：选择多份文件进行对比、汇总与问答，显示来自哪些文件和段落；批量改写先列出文件及差异，再逐份或按勾选确认。搜索结果可作为明确选择的上下文，避免默认上传整个工作目录。大文档分段处理并明确上下文范围。

所有修改默认先预览差异，再选择替换选区、插入光标处或生成新文档；确认前核对原文版本，支持撤销。多文件问答需设计检索及引用，不直接把整目录塞进一次请求。默认不执行模型生成的命令、不自主删除文件。

验收：本地协议与错误回归，随后逐服务使用用户提供的 API 凭据做真实调用。模拟服务、模型列表读取与成功生成分别记录；不把一种服务的成功扩展为全部平台已验证。

## 4. 百度网盘同步

### 接入前置

先确认百度网盘开放平台应用接入、当前账号类型的权限、允许的云端路径、授权流程、令牌刷新及接口限制。网页登录授权由用户完成，不收集百度账号密码；不能承诺普通账号仅一次授权就取得任意目录读写权限。

如果所需授权流程要求保密的应用 Secret，公共桌面程序不能内置可提取的共享 Secret；需选择平台允许的桌面授权方式或配套授权服务。是否需要服务端，须在接入验证后确定，规划阶段不假设已支持 PKCE 等具体能力。

### 用户流程与同步规则

- 同步中心：连接账号 → 选择本地目录与获准云端目录 → 选择类型和模式 → 预览待同步清单 → 执行。
- 模式包含上传备份、下载到本地及双向同步。先交付手动单向上传/下载，再实现自动和双向同步。
- 默认只同步已保存文件，支持 Markdown 引用的图片/附件；不上传 API Key、授权令牌、程序配置、历史记录和恢复草稿。上述非内容项如以后需要跨设备支持，应单独设计。
- 记录最后一次成功同步基线及文件哈希/云端标识；不只比较修改时间，不自动使用最新时间覆盖两端改动。
- 两端同时修改时保留冲突副本并让用户选择；云端文件覆盖本地前检查未保存文档，成功后才提示重载。
- 删除传播默认关闭，开启后明确预览；失败、取消和断网不当作删除或完成。限流遵循平台响应，重试须具备去重依据。
- 显示进度、暂停/恢复、失败原因、上次成功时间、待同步数量和冲突列表；取消授权时停止任务并清理本机令牌。

验收：真实用户授权、上传/下载逐字节核对、过期令牌、断网与限流、两端修改、重命名和删除、未保存文档保护。自动同步以保存事件和延迟合并触发，具体轮询限制依据平台规则。

## 5. 其他建议（未列为已确认开发范围）

优先建议：Markdown 标题大纲与跳转、收藏和标签、文件内容版本快照与对比恢复、命令搜索面板。

后续候选：内部文档链接与反向链接、图片粘贴到附件目录、文档模板与片段、工作区预设、WebDAV 等其他同步服务适配。保持默认收起与按需加载，不在首版增加通用插件平台或自主执行 AI 代理。

## 实施顺序

1. 文件搜索及打开历史，形成可用的文档入口。
2. 多平台 AI 配置、连接测试与首批文本功能。
3. 标题大纲、模板/收藏等已获确认的可选功能。
4. 百度网盘接入可行性验证与手动单向同步；接入调研可与前几阶段交错开展。
5. 冲突处理、双向/自动同步；再评估多文档 AI 检索与其他云服务。

下一步先确认方案和可选功能范围，再做实现。每阶段更新开发包和可恢复升级包，保留配置迁移与恢复路径。本文没有宣称上述新功能已经实现。
