### 协议

请求按 Chat Completions 文本协议构造 model、stream:false 和 system/user 消息。默认操作包括解释、翻译、改写、生成，另可传入补充说明。默认解释与翻译使用中文；改写保留原语言和含义，生成按用户说明输出。模型名由配置提供，不硬编码供应商或模型。输入按 UTF-8 验证，控制字符和引号/反斜线做 JSON 转义。

请求输入上限 256 KiB、模型名 256 字节、补充说明 4096 字节。响应上限 2 MiB，先严格验证完整 JSON，再读取首个 choices 的 message.content，解码转义和 Unicode 代理对。拒绝空文本、null、非法 UTF-8、孤立代理、NUL 和重复的目标字段；如果服务提供 finish_reason，则只接受 stop，其他终止原因标记不完整，不能视为可应用的完整结果。兼容只返回内容而不提供终止原因的服务。

协议核对使用 OpenAI Docs 的[官方创建 Chat Completion 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。这里是文本兼容协议实现，不宣称已验证任一远程供应商或模型。

### 凭据与地址

密钥通过 Windows Credential Manager 的 Generic Credential 保存到 Notepad3/AI/<profile>，不写应用 INI。profile 限制长度和字符；密钥限制 2048 字节及可打印非空白 ASCII，拒绝换行头注入。读取结果由调用方拥有，AiCredential_Free 清零并释放。保存、读取、更新及删除返回实际 Windows 状态。

服务完整 URL 接受 HTTPS；本地 HTTP 只接受 localhost、127.0.0.1 或 IPv6 回环，不允许远程明文 HTTP、URL 用户名/密码、片段或控制字符。第二十六轮 HTTP 层已接入默认系统 TLS 校验、重定向拒绝和等待期间取消。合法远程服务、代理环境与用户凭据仍待实际验证。

## 第二十六轮：HTTP 传输

每个服务 origin（scheme/host/port）保留一个异步 WinHTTP 客户端，防止连续请求反复创建会话导致运行时资源持续增加；同一客户端一次执行一个请求，冲突返回 Busy。客户端不能复用到另一 origin，由调用方持有直到工作返回。远程采用系统自动代理，回环不走代理。自动 Cookie 和认证、重定向关闭，显式 Bearer 头按可打印 ASCII 验证。

AiHttp_Run 在后台工作线程调用，网络发送、接收头和读取均异步，由独立状态事件等待，每 50 ms 检查取消和全程截止时间（100 至 120000 ms）。取消/超时通过关闭异步请求中止等待；请求体、读取缓冲及状态由 shared_ptr 保留直到 HANDLE_CLOSING 最后通知，避免取消后回调访问已经释放的数据。授权头在状态销毁时清零。协议解析前后再检查取消及期限，非成功情况不产生可应用内容。

实现依据微软[关闭异步请求与最后回调的说明](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpclosehandle)；不对同步请求做跨线程强制关闭。HTTP 状态、WinHTTP 错误与协议状态分别保留，200 响应仍须通过完整文本协议解析。总下载 2 MiB 超限停止，不自动重发业务操作。

## 第二十七轮：配置、操作面板与安全应用

“查看 → AI 助手”打开底部面板。服务接口地址须填写完整 chat-completions URL，模型由用户指定，超时 100–120000 毫秒。保存配置写 Settings2 的 AIEndpoint、AIModel 和 AITimeoutMs；密钥仅写 Windows Credential Manager，留空保留当前服务密钥，删除密钥为独立操作。完整 URL 的 SHA-256 生成 service-<hash> profile，改变主机、端口或路径都选择不同凭据。配置保存失败时回滚本次密钥修改并保持运行配置；无保存权限时不修改 INI 缓存。

解释、翻译和改写使用单一选区，空选区使用全文；生成使用附加要求作为请求输入，结果应用到选区或光标插入点。拒绝矩形/多选区，输入限额 256 KiB。后台任务拥有不可变的原文、文档标识/版本、目标范围、选区及服务客户端；只在任务完成后由窗口定时器发布结果。关闭面板取消工作，任务拥有资源直至真正结束，重新打开面板不会接收旧结果。每服务客户端跨面板关闭保留以避免运行时句柄增长。

原文和结果使用只读 RichEdit；去除相同首尾后的改动区分别红/绿着色，按 RichEdit 段落索引统一 CR/LF，并避免拆分 UTF-16 代理对。这是整体改动区预览，尚不是逐行、多处差异的精细对齐。解释不可应用。其他结果由“应用结果”明确触发，必须当前文档、版本、单选区锚点和光标完全符合请求快照，原文字节独立一致且文档可编辑，否则拒绝并提示重新请求。替换单一撤销事务，成功后禁用按钮；同一结果不能重复应用。
