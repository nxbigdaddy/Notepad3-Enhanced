## 第二轮：实际预览加载验证

用户要求打开 Markdown 并查看渲染。新增 `/mdpreview` 启动参数，使用 `/n /mdpreview document.md` 可直接打开预览，不依赖窗口控制工具发送快捷键。

实际诊断发现 WebView2 的 NavigateToString 在本机报告 `data:text/html` 导航，原先只允许 `about:blank` 的策略把宿主页面也拦截了（导航错误状态 14）。已修复：仅允许宿主待处理渲染发起的非用户 HTML data 导航，继续阻止用户 data、外部和脚本导航；处理器使用弱引用避免循环持有预览状态。

修复版已实际启动并打开 tests/fixtures/preview.md。artifacts/preview-demo-fixed.log 记录环境初始化、控制器创建及 navigation-completed 全部返回 0x00000000。页面加载的运行证据已取得；截图工具仍有窗口身份绑定错误，因此视觉布局、滚动、实时输入和图片显示还没有完整验收。

新增 5 项导航回归检查，总计 17 项通过。完整 x64 构建通过。修复版开发包在 artifacts/markdown-x64-v2/Notepad3.exe，本次展示窗口从该包启动并保留供用户查看。

构建时发现语言项目的并行 MUI 拆分共享 np3lng.dll 导致偶发失败，构建入口改为项目串行 `/m:1`。打包入口支持 `-PackageName`，可输出新目录以避免覆盖正在运行的开发包。可选诊断环境变量 NP3_MARKDOWN_DIAGNOSTICS 仅记录初始化和导航状态，不记录文档内容。

下一轮从修复版继续验证实时更新、图片、反复开关、布局与滚动，不要重新认定页面仍被拦截；其他未完成范围保持不变。以下第一轮记录保留为历史证据。
